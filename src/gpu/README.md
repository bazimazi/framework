# src/gpu

The backend-agnostic GPU API (SPEC §12.1, D-25, D-38). Internal: games draw through draw2d; nothing here is in `bmf.h`.

## Files
- `gpu.h`: the API (task 1A-13). Generational handles (`bmf_gpu_buffer/texture/sampler/pipeline/bindset`, one-member structs around a `u32` so kinds cannot be mixed up), descriptors, frame/pass/draw calls, two-phase readback, stats. Every function has its contract comment.
- `gpu.c`: the frontend. Handle pools, validation, frame and pass state, stats. With `BMF_GPU_BACKEND_NULL` it is the whole backend (D-38): every call is validated and counted, nothing is rendered. Backends hook in at the `#if BMF_OS_WINDOWS` blocks (some marked `// backend:`).
- `d3d11/gpu_d3d11.c` (1A-14): the D3D11 backend, included by `bmf.c` before `gpu.c` on Windows. Static `gpu_d3d11_*` functions that `gpu.c` calls at its `backend:` points (inside `#if BMF_OS_WINDOWS`). Done so far: (1A-14a) device (hardware, WARP fallback, WARP when `software`), flip-model swapchain, frame-latency wait, present, occlusion, resize, passes (bind, viewport, clear), debug-layer message queue, device-lost panic; (1A-14b) buffers, textures with their views, samplers; (1A-14c) pipelines, bind sets, draws, readback.
- `webgpu/` (1B-42): empty so far.

## Invariants
- No bound state (D-25): every `bmf_gpu_draw` names its pipeline, bind set and vertex buffers. Backends skip redundant state changes themselves.
- All validation is in the frontend and identical for every backend, so the null backend in a native test catches what WebGPU would reject. Validation = `BMF_ASSERT` (debug only); each assert expression ends in a message `"bmf_gpu_<fn>: <rule>"`, which the crash JSON line prints. Backends never re-validate.
- Backends store native objects in arrays indexed by the frontend's pool slot index (`gpu_handle_slot`).
- The surface (window back buffer) is an ordinary texture slot with `is_surface` set: `RENDER_TARGET` only, cannot be destroyed, sampled or read. It exists only when `bmf_gpu_init` got a window.
- Pipelines bake in the target formats (WebGPU rule): a draw's pipeline `color_format`/`depth_format` must equal the pass's targets exactly (a pipeline with depth NONE cannot draw in a pass with a depth target).
- A bind set is made for a shader id and is usable with every pipeline of that shader. Slot i = HLSL `b<i>`/`t<i>`/`s<i>`; WGSL `@group(0)` bindings i / 8+i / 16+i.
- Vertex attribute location L = HLSL semantic `ATTR<L>`, WGSL `@location(L)`.
- Buffer writes (WebGPU queue-write semantics): between two `end_frame` calls (one "write period"), writes to one buffer go to increasing, non-overlapping ranges. Dynamic buffers: bytes not written in the current period are undefined (D3D11 `MAP_WRITE_DISCARD`). UNIFORM buffers are written only when `dynamic` (D3D11 cannot safely update part of a default constant buffer: it allows that only with `NO_OVERWRITE`/`DISCARD`, which would race frames in flight or drop the other bytes); constant uniform data goes in at create.
- Destroying resources and resizing the surface happen outside a frame. Bind sets referring to a destroyed resource may live on but must not be drawn with (checked at draw).
- Readback is two-phase because WebGPU maps asynchronously: `read_begin`, then `read_end` until it stops returning `BMF_ERR_PENDING`. One read in flight. The null backend returns `BMF_ERR_UNSUPPORTED` from `read_begin` (the `shot` command maps it to `no_gpu`).
- Portable limits are the stricter of D3D11 and WebGPU defaults: buffers ≤ 256 MiB, uniform buffers ≤ 64 KiB with 256-byte binding offsets, textures ≤ 8192², vertex stride ≤ 2048, 16 vertex locations.

- D3D11: `d3d11.dll` is loaded with `LoadLibraryExW(..., LOAD_LIBRARY_SEARCH_SYSTEM32)` once per process and never unloaded. The device is single-threaded (main thread rule), feature level 11_1 or 11_0. Required: the D3D11.1 runtime (`ID3D11DeviceContext1`, which replaces the plain context) and the `D3D11_OPTIONS` `ConstantBufferOffsetting` and `MapNoOverwriteOnDynamicConstantBuffer`; a hardware device without them is dropped for WARP. The DXGI factory comes from the device's adapter (a swapchain must come from the factory that made the device).
- D3D11 buffers: dynamic = `USAGE_DYNAMIC`, written with `Map(WRITE_DISCARD)` on the first write of a period and `Map(WRITE_NO_OVERWRITE)` after (safe by the increasing-ranges rule; draws already submitted keep their memory). Default = `USAGE_DEFAULT`, written with `UpdateSubresource1` (vertex buffers only). Default buffers without data are zeros: up to 64 KiB from a static zero array as initial data, larger in 64 KiB `UpdateSubresource1` copies.
- D3D11 textures: one mip, the `_SRGB` DXGI format for RGBA8_UNORM_SRGB (sampling decodes, rendering encodes), `IMMUTABLE` when created with data and not a render target. Views by usage: SRV for SAMPLED, RTV for color RENDER_TARGET, DSV for depth. COPY_SRC needs no bind flag (readback copies to a staging texture). Destroying a texture first unbinds the output merger.
- D3D11 samplers: point or `MIN_MAG_LINEAR_MIP_POINT` (no mips), CLAMP or WRAP on U, V and W, anisotropy 1.
- D3D11 shaders (1A-15, D-14): `build.c` compiles every top-level `shaders/d3d11/<name>.hlsl` (entries `vs_main`/`ps_main`, `vs_5_0`/`ps_5_0`, strictness and warnings-as-errors; debug `DEBUG|SKIP_OPTIMIZATION`, release `OPTIMIZATION_LEVEL3`) into `out/gen/shaders_d3d11.h`: the `bmf_shader_id` enum (`BMF_SHADER_<NAME>` in file name order, `BMF_SHADER_COUNT`), both bytecode sets (picked by `BMF_DEBUG`) and `gpu_d3d11_shader_codes[shader id]` with the b/t/s registers each shader declares (VS and PS together, read from the bytecode's RDEF chunk; debug and release must agree). `gpu_d3d11.c` includes it. Other files under `shaders/d3d11` (subfolders, `.hlsli`) are `#include` material. It is regenerated when the files under `shaders/d3d11` or the compiler change; `build win64`/`build test` do that first, `build shaders` does only that. Test shaders (`tests/shaders/d3d11/`) go through the same generator into `out/gen/test_shaders_d3d11.h` (ids from `GPU_TEST_SHADER_FIRST` = 56, `build test` only); tests copy them into the table. A pipeline for an id without bytecode panics with the id and pipeline label.
- Shader rules checked at build time: file names `[a-z][a-z0-9_]*.hlsl`; only cbuffers (b0..b3), textures (t0..t7) and samplers (s0..s3); at most 56 runtime shaders (test shaders take ids 56..63, at most 8). Release bytecode is reproducible; debug bytecode is not (`D3DCOMPILE_DEBUG` embeds a PDB GUID), so regenerating rebuilds debug binaries.
- D3D11 pipelines: every object is created at `pipeline_create` (vertex/pixel shader, input layout with semantic `ATTR<location>` and per-instance step rate 1, blend, rasterizer, depth-stencil state). Blend: OPAQUE off, PREMULTIPLIED ONE/INV_SRC_ALPHA, ADDITIVE ONE/ONE (alpha the same). Rasterizer: solid, `FrontCounterClockwise`, depth clip on. Depth: test = LESS_EQUAL, write without test = ALWAYS, neither = off; stencil off.
- D3D11 bind sets: resolved at create into ready-to-bind arrays (constant buffers with `first constant = offset / 16` and a count rounded up to a multiple of 16 constants, the D3D11.1 rule; SRVs; samplers), each holding a reference (AddRef/Release) like a WebGPU bind group, so a resource destroyed before the bind set cannot dangle. Bound to VS and PS, all slots at once (`VS/PSSetConstantBuffers1`, `...ShaderResources`, `...Samplers`).
- D3D11 draws: `begin_pass` unbinds every SRV (a texture sampled earlier may now be a target) and forgets the bound state; a draw then sets only what changed since the previous draw of the pass (pipeline objects, bind set, each vertex buffer + offset), and `DrawInstanced`.
- D3D11 readback: `read_begin` copies into a new staging texture; `read_end` maps it (waits for the GPU), honors `RowPitch`, swaps BGRA to RGBA, releases the staging texture. Never `BMF_ERR_PENDING`.
- D3D11 swapchain: `FLIP_DISCARD`, 2 buffers, BGRA8_UNORM, `SCALING_STRETCH`, `FRAME_LATENCY_WAITABLE_OBJECT` with maximum latency 1, `ALLOW_TEARING` when supported (used when vsync is off), DXGI Alt+Enter disabled (fullscreen is borderless, platform layer). The surface slot's render target view is recreated on resize.
- D3D11 frame pacing: `begin_frame` waits (1 s timeout) on the latency object once per presented frame: a frame that does not present keeps its "token", so the next frame does not wait again. A minimized window (`IsIconic`: flip-model `Present` keeps succeeding at once while minimized on Windows 11) or an occluded `Present` makes `begin_frame` return 0 without waiting (after an occluded present it only runs `Present(DXGI_PRESENT_TEST)` until that succeeds); surface passes are then validated and dropped by the frontend.
- D3D11 errors: device removed/reset/hung from any call = `bmf_panic("bmf_gpu: D3D11 device lost in <call>: <HRESULT>, removed reason <HRESULT> ...")`; a failed create = panic naming the call and the object label. With `debug_layer`, layer errors and corruption messages panic (backend bugs) and warnings go to stderr as `{"event":"warning","source":"d3d11",...}`; a missing layer (Windows optional feature "Graphics Tools") prints one warning and runs without it.

## Data layout
- `gpu_frontend` (one static struct): five `bmf_pool`s with their slot arrays, per-slot info (`gpu_buffer_info`, `gpu_texture_info`, copies of sampler/pipeline/bind set descriptors), frame/pass state, two `bmf_gpu_stats` (frame in progress, last completed). About 73 KiB of `.bss`, most of it 64 pipeline and 256 bind set descriptor copies.
- Pool capacities: buffers 256, textures 256 (incl. the surface), samplers 32, pipelines 64, bind sets 256. A full pool is a `bmf_panic` (fixed budget).

- `gpu_d3d11_state` (one static struct): device, context, debug interfaces, swapchain and latency handle, surface size and pacing flags, and native objects per frontend slot: buffers (+ dynamic flag), textures, SRVs, RTVs, DSVs (256 each), samplers (32), `gpu_d3d11_pipeline` (64, 6 objects + topology + strides) and `gpu_d3d11_bindset` (256, 4 constant buffers with ranges, 8 SRVs, 4 samplers), the per-pass bound-state cache and the readback staging texture. About 56 KiB. Shutdown releases whatever is still non-zero in these arrays.

## Hot paths
- `bmf_gpu_draw`: release = a few compares and counter updates; debug adds handle checks, format checks and an O(attributes) vertex range check per vertex buffer. D3D11 backend: compares against the per-pass bound state, then only the changed `*Set*` calls and `DrawInstanced`. Measured (debug build, 10 000 draws, CPU submit time): Intel UHD 770 360 ns/draw with identical state, 670 ns/draw with pipelines alternating every draw; WARP 3.5 / 5.5 µs (the software driver), 4.7 / 7.1 µs with the debug layer.
- `bmf_gpu_buffer_write`: O(1) bookkeeping plus the backend copy.

## Limits
- Main thread only.
- No index buffers, storage buffers, mipmaps, MSAA, scissor, viewport other than the full target, texture uploads after creation, or compute. Add them with their first user.
- Shader ids are range-checked (`0..BMF_GPU_MAX_SHADERS-1`) by the frontend. Bind sets are checked against the shader's declared registers (exactly those slots filled) only with the D3D11 backend, which has the generated metadata; the null backend has none.
- WebGPU returns `BMF_ERR_UNSUPPORTED` until 1B-42.
- `tests/test_vtable_slots.c` is a host check, not a unit test: `build test` builds and runs it first (see `tools/test/README.md`).
- D3D11 has no device-loss recovery (panic). No exclusive fullscreen, HDR or MSAA swapchain.

## Tests
`tests/test_gpu.c` (lifecycle with and without a surface, a two-pass two-frame API usage run with exact stats, handle staleness and slot reuse, five expected-crash validation tests: draw outside a pass, pipeline/pass format mismatch, overlapping writes in one period, vertex read past the end, writing a non-dynamic uniform buffer). `tests/test_gpu_d3d11.c` (WARP with the debug layer: headless start with hardware request and forced WARP, hidden, shown, minimized and restored window presenting, 1000-resize leak check through `ID3D11Debug` live objects, HRESULT names, device-lost panic as an expected crash, buffer contents for every write path through a staging readback (with a queued GPU copy between ring appends so a wrong DISCARD is caught), every texture format/usage and sampler with offscreen passes, live objects back to baseline after destroy, shutdown releasing leftovers; exact pixels for clears (RGBA8, BGRA8, sRGB encode), one triangle with analytically known coverage (vertex + instance streams, `first_instance`, uniform binding at an offset that is the buffer's last 16 bytes, culling), point-sampled RGBA8/R8 textures copied exactly, premultiplied/additive blending and depth testing, plus a draw-submit timing note; the generated shader tables (DXBC bytecode for every id, the declared registers of the test shaders) and an expected crash for a bind set that misses a declared slot).
