# src/core

The game model and the engine loop (SPEC §8, D-20, D-21, D-32, D-39, task 1A-23): `bmf_game_desc` validation, memory and the state block, the fixed-step clock, ticking with per-tick input, simulation-to-presentation events, the frame loop (window, GPU, draw2d, frame pacing) and hot reload of the game DLL.

## Files
- `../bmf.h` (public, section "The game model"; `BMF_API_VERSION` is at the top of the header): the game limits (`BMF_CORE_DEFAULT/MIN/MAX_TICK_RATE`, `_MAX_STATE_SIZE`, `_MAX_SFX_PER_TICK`, `_NAME_MAX`), `bmf_field_type`/`bmf_field`, `bmf_field_type_size`, `bmf_ctx`, `bmf_game_desc`, `bmf_game`, `bmf_sfx_play`.
- `core.h`: the engine interface (`bmf_core_parse_args`, `_check_game`, `_start`, `_stop`, `_step`, `_advance`, `_alpha`, `_draw`, `_set_view`, `_swap_game`, `_get_stats`, `_reflect` (the running game's `bmf_reflect`), `_display_open/close`, `_display_is_open`, `_frame`, `_run`, `_print_error`, `_ctx`, `_state`, `_game`, `_memory`, `_running`, `_phase_name`, `_view`, `_state_hash`, `_load_state`, `_build_id`, `_capture`, `_request_quit`, `_quit_requested`, and in DLL builds `_dll_open`, `_dll_reload`). Every function has its contract comment.
- `core.c`: everything above. Included by `bmf.c` after input (it uses every module); `win32_main.c` (the exe entry) comes after it.

## Invariants
- `bmf_core_check_game` is the single validation of a game: api version, name 1..63 bytes, state size 1..1 GiB, tick rate 0 (= 60) or 30..240, memory sizes 0..4 GiB, all three callbacks, the field table (`bmf_reflect_check_fields`, src/debug: names 1..63 bytes of `a-z A-Z 0-9 _ .`, unique and not `tick`, known type, count >= 1, inside the state block, offset aligned to the scalar size, `count_field` only on arrays and naming an I32 scalar field anywhere in the table), in debug builds `state_layout_hash == bmf_fields_hash(fields)` (the message gives the value to declare), and the action table (`bmf_input_check_actions`). Every failure is one line naming the game, the field or action and the rule; the runtime prints it as `{"event":"error","error":"invalid_game","detail":...}` and exits 1.
- One engine per process. In debug builds the game DLL contains only the engine headers, `base_builtins.c` and the game; every other engine call goes to the exe, which exports its `bmf_*` functions (build.c reads them from the object's COFF symbol table into a `.def`) and writes `game.lib` for the DLL to link against. So draw2d, input and core state exist once, in the exe, and survive DLL reloads.
- The state block is pushed zeroed and 64-byte aligned from the `game_state` arena before `init` (D-37 rule 2). The arena reserves `max(state_size, options.state_reserve)`: the debug exe reserves 256 MiB of address space (committed only when used) so a reload may grow the state.
- Clock: the accumulator is an integer in ns x tick_rate, one tick = 10^9 units, so no rounding drift (60 frames of 16 666 667 ns = 60 ticks). Per frame: elapsed real time clamped to 0..1 s, times `--scale`, then at most 4 ticks (`BMF_CORE_MAX_STEPS_PER_FRAME`); owed whole ticks beyond that are dropped and counted (`ticks_dropped`), the fraction is kept. `alpha` = fraction in [0, 1). A tick-rate change clears the accumulator.
- Per tick (`core_tick_once`): assert the FPU state (debug), `bmf_input_sample_tick`, `tick(cx, state, &in)` with `cx->tick` = index of this tick, then deliver the tick's events. `cx->tick` outside tick = ticks completed. `cx->dt` = `1.0f / tick_rate` (real division).
- `bmf_sfx_play` only in init and tick (asserted); up to 256 per tick, the rest dropped and counted. Delivery is an audio stub until M7 (counted in `sfx_played`). Events are not state and are not hashed.
- The engine keeps its own copy of the action table (names included), so input never points into an unloaded DLL. A reload re-inits input only when the table differs (rebinding is kept otherwise).
- Hot reload (`bmf_core_swap_game`): the new game is checked first; invalid, or a state larger than the reserve, is `REJECTED` (old game keeps running). Same `state_size` and `state_layout_hash`: `KEPT` (state and tick untouched, new code runs). Otherwise `RESET`: zeroed block, `init` with the same seed, tick 0. The tick rate follows the new game unless `--tick-rate` was given. The memory budget is fixed at start.
- DLL watching (`BMF_GAME_LINK_DLL`): `game.dll` is never loaded itself (the linker must be able to overwrite it). It is copied to `game_0.dll` / `game_1.dll` alternately and the copy is loaded; the old copy is unloaded only after the new game was swapped in. A change is loaded once the file was unchanged for one poll interval (250 ms) after it changed, so a half-written DLL is not loaded; a copy that still fails to load is reported (`{"event":"reload","state":"rejected",...}`) and retried at the next change. Successful reloads print `{"event":"reload","state":"kept"|"reset","tick":T,"ms":M}`.
- Frame (`bmf_core_frame`): DLL poll; pending resize applied (outside the GPU frame); with `--control` the queued protocol requests (`bmf_protocol_poll`, outside the GPU frame so `step` and `shot` can run; headless and paused it blocks for the next request; a `quit` ends the frame here); minimized: pump events and sleep 16 ms, no ticks, the clock restarts on restore; `bmf_draw2d_begin_frame`; `bmf_gpu_begin_frame` (D3D11 windowed: waits on the frame-latency object, so input is pumped after the wait); events to input (resize is deferred to the next frame) and gamepads; ticks (`--control`: only while `run` is in effect, real-time clock, 1 ms sleep per headless frame; windowed: real-time clock; headless: exactly one tick per frame, as fast as possible); `draw`; one pass to the surface or the headless offscreen target (`--size`, default 1280 x 720, `bmf_gpu_surface_format`), cleared to (0.06, 0.07, 0.09); flush; end frame; frame arena reset. An occluded window does not get paced by the swapchain, so the frame sleeps 16 ms instead.
- Display: windowed = D3D11 hardware with vsync, debug layer in debug builds; `--headless` = no window, D3D11 WARP offscreen; `--no-gpu` (or D3D11 unavailable) = the null backend. Window drags and resizes block the loop (Windows modal loop); nothing renders meanwhile, and the 1 s clamp plus the 4-tick cap bound the catch-up.
- Command line (SPEC §11.1): `--headless --control --no-gpu --replay FILE --verify --profile --seed N --tick-rate N --scale X`. Unknown flags and bad values are `bad_args` errors. `--control` starts the control protocol paused (src/debug/protocol.h); a release build without `BMF_AGENT=1` answers it with `not_supported`. `--replay FILE` plays a recording (src/debug/replay.h) with its seed and tick rate and quits at its end; with `--verify` it runs without a display as fast as possible and exits 0 (all checkpoints match) or 1; with `--control` the replay is loaded and the protocol's steps consume it; with `--profile` (task 1A-42; not with `--control` or `--verify`) the run prints the profile report of the whole run as one `{"event":"profile","ticks":N,...}` line (the `profile` response's keys) before its quit line (perf budgets, tools/test/perf.c). A release build without `BMF_AGENT=1` answers `--control` and `--replay` with `not_supported`. `--scale` is the real-time speed of the windowed loop (0.01..100). `--size WxH` (16..8192 each) sets the headless target and the initial window client size.
- Simulation identity: `bmf_core_state_hash` = bmf_hasher (seed 0) over the tick count (8 bytes LE) and the state block (debug builds first scan the reflected floats and assert on NaN/Inf, D-37 rule 11); `bmf_core_load_state` replaces both (replays, snapshots); `bmf_core_build_id` = `BMF_BUILD_ID` from build.c, combined in debug DLL builds with the game DLL's `bmf_game_build_id()`.
- Capture (`bmf_core_capture`, the `shot` command): a GPU frame of its own between engine frames: draw2d frame, the game's draw with the current alpha, one pass into the headless target (same size) or a temporary RENDER_TARGET | COPY_SRC texture, readback to RGBA. The view the game sees is the current one, or W x H at DPI scale 1; `core.view` and `ctx.view_size` are restored. Presents nothing; the null backend returns `BMF_ERR_UNSUPPORTED`.

## Data layout
One static `core` struct: the game description copy, options, the `bmf_memory` arenas, the state pointer, `bmf_ctx`, clock (tick, accumulator), stats, the action table copy (73 actions of 32 bytes + 73 x 32 name bytes, about 4.6 KiB; the whole struct about 8.3 KiB), the sfx queue (256 x 12 bytes), display state (view, offscreen texture, pending resize, suspended/quit flags, last frame time). DLL builds add `core_dll` (three paths, the loaded library, the file watch). No heap.

## Hot paths
- `bmf_core_advance` / `core_tick_once`: O(1) bookkeeping around `bmf_input_sample_tick` and the game's tick. Not measured separately; the frame cost is the game's tick and draw plus draw2d and the GPU.
- `bmf_core_frame`: one DLL poll (a file-info syscall at most every 250 ms), event pump, ticks, draw, one pass, one flush.

## Limits
- Hot reload keeps the memory budget, the state reserve (256 MiB in debug) and the seed of the run. Static data inside the game DLL is lost on reload (all state belongs in the state block, D-21).
- Headless free-run without `--control` never ends by itself (smoke runs only). `bmf_core_request_quit` (protocol `quit`, end of stdin) ends the frame loop. In debug and `BMF_AGENT` builds every tick takes its input from a playing replay when there is one, is recorded (`bmf_replay_record_input`), and ends with `bmf_replay_after_tick` (checkpoints) and `bmf_protocol_after_tick` (input holds, watches); `bmf_core_start` clears the snapshot slots, registers the crash dump hook (src/debug/crash.h), starts the profiler and clears the log (src/debug/profile.h) and starts the session recording, and a game swap restarts it; `bmf_core_dll_reload` reloads the game DLL on request (protocol `reload`).
- No rendering during window drag/resize. Simulation pauses while minimized.
- Audio: sfx events are counted only (M7).
- Hot reload compares `state_size` and the declared `state_layout_hash`; in debug the declared hash must equal `bmf_fields_hash`, so a changed field table is first rejected with the new hash, then reset once the game declares it.

## Tests
`tests/test_core.c`: check_game (every rule and message), parse_args (every flag and error except `--size`, which `tests/test_shot.c` covers), start_init (zeroed aligned block, init once with seed, dt bits, tick-rate override and default, failed start), fixed_step (exact 60 Hz accumulation, alpha, 4-tick cap and dropped count, 1 s clamp, rates 30/60/120/144/240, time scale), tick_input_events (tick indices, input edges per tick with an injected press, sfx delivery and overflow), swap (kept with rebinding kept, reset with seed, growth within the reserve, rejected invalid and oversized, changed action table and tick rate), frame_null (three headless frames on the null backend), frame_d3d11 (one WARP frame read back: circle and clear color pixels), sfx_in_draw (expected crash). The DLL copy/load/watch path is checked by running `games/_loop` (task 1A-23 note in PLAN.md).
- Profiler zones (task 1A-36): `tick` around the game's tick, `draw` around its draw, `draw2d_flush` and `gpu_end_frame` in the frame, `debug_hooks` around the per-tick recording and the after-tick hooks; each frame's duration (without the sleeps at its end) goes to `bmf_profile_frame`. `bmf_core_run` turns the log echo on in `--control` mode. `bmf_core_check_game` checks `zone_names` (0..32 names of 1..63 bytes).
