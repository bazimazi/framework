# src/draw2d

Batched instanced 2D renderer (SPEC §12.2, task 1A-20). Built on `src/gpu` (internal API). Games submit shapes with `bmf_draw_*`; the engine brackets frames with `bmf_draw2d_begin_frame` and renders with `bmf_draw2d_flush` inside a GPU pass.

## Files
- `../bmf.h` (public, section "Drawing"): cameras (`bmf_camera`, `bmf_camera_world_default/screen_default/world_to_screen/screen_to_world`, `bmf_draw_camera_push/pop`), the shape calls (`bmf_draw_rect`, `_rect_rounded`, `_circle`, `_ring`, `_line`, `_triangle`) and text (`bmf_text_measure`, `bmf_draw_text`).
- `draw2d.h`: the engine side: instance format (`bmf_draw_instance`, 48 bytes), kinds, sort key layout, `bmf_draw_f16`, the engine interface (`bmf_draw2d_init/shutdown/begin_frame/flush/get_stats`, `bmf_draw2d_view`) and `bmf_draw_sprite`, which stays internal until the asset tasks (1B-32, 1B-33) give games a public texture handle. Every function has its contract comment.
- `draw2d.c`: state, submit, sort, gather, upload, batching, pipeline and bind set caches. Included by `bmf.c` after `gpu.c`.
- `font_stroke.c` (1A-21): the built-in stroke font (glyph table authored as polyline text, parsed once into a segment table), `bmf_text_measure` and `bmf_draw_text`. Included after `draw2d.c`.
- `shaders/d3d11/draw2d.hlsl` (shader id `BMF_SHADER_DRAW2D`): the single pipeline. Vertex shader: per-kind quad (centered rotated box for RECT/CIRCLE/SPRITE, segment box with round caps for CAPSULE/GLYPH, bounding box for TRIANGLE), padded by 1 px + softness for the antialiased fringe; passes the shape parameters as `nointerpolation` values. Pixel shader (1A-20b): exact signed distance d in target pixels at the pixel center (`SV_Position.xy`): rounded box (RECT with its corner radius clamped to the shorter half side; SPRITE with radius 0), circle, capsule (CAPSULE, GLYPH), triangle (either winding); stroke s > 0 keeps the band `abs(d + s/2) - s/2`; coverage `saturate(0.5 - d / (1 + softness))`; output color * texture (SPRITE) * coverage, premultiplied.

## Invariants
- Instance coordinates are target pixels, y down. Submit calls take camera-space values (D-19): each layer has a camera stack (depth 8), reset at `begin_frame` to the default WORLD camera (y up, meters, 64 logical px/m, world origin at the view center); a SCREEN camera is y down, logical pixels, origin top-left. The layer's current camera is kept as a transform to target pixels (`draw2d_transform`: m3x2, scale, rotation) computed at push/pop for `begin_frame`'s view (physical size and DPI scale: logical px x DPI = target px). Submits apply it at once: points through the matrix, lengths (sizes, radii, thickness, corner radius, stroke) times the scale. The shader never sees a camera, and cameras never split a batch.
- Rotation: API angles are counter-clockwise on screen in every space (D-19). A camera's `rotation` turns the view counter-clockwise (content appears turned clockwise, around the view center for WORLD, the top-left for SCREEN). The instance stores `camera rotation - angle` (the y-down pixel-space angle the shader rotates by). Sprites stay upright in WORLD space: only points are mapped (with the y flip), the quad's frame comes from the rotation, so uv (0, 0) is the on-screen top-left at rotation 0.
- `bmf_camera_world_to_screen` / `screen_to_world` map camera space and screen logical pixels for a view size; they use `bmf_sincosf` (deterministic), so input may map pointers in tick.
- Text (1A-21): glyphs for ASCII 32..126 plus a replacement box, as polylines on an integer grid: em (line height = font size) 64 units, baseline 48 below the line top, caps 44, x-height 32, descenders -12. Every point lies in x 3..advance-3, y -12..45, so strokes up to `BMF_TEXT_MAX_CONTAINED_STROKE` (6/64 of the size; default 0.08) keep the ink inside the measured box. Each segment is one GLYPH instance (capsule SDF, white texture: text batches with shapes). Layout is integer advances (side bearings included, digits tabular), `\n` new line, `\r` nothing, other code points and invalid UTF-8 bytes the replacement glyph; measure and draw share `font_stroke_line_units`. Text is laid out in screen orientation: the down axis is the camera's +y (SCREEN, transform determinant > 0) or -y (WORLD), so text is upright in both and turns with a rotated camera.
- Colors stay straight-alpha sRGB `bmf_color` in the instance; the pixel shader premultiplies. `color` is read as `U8X4_UNORM`, whose little-endian bytes are A, B, G, R, so the shader swizzles `.wzyx`.
- f16 fields (corner radius, stroke, softness) are non-negative lengths in pixels, rounded to nearest even, saturated at 65504 (`bmf_draw_f16`, tested over every half value and midpoint).
- Sort key: layer(8) | pipeline(4) | texture(12) | depth(24) | seq(16). pipeline = 0 (premultiplied only), texture = GPU texture slot index, depth = seq = 0. The radix sort is stable, so equal keys keep submission order; leaving seq at 0 also lets the sort skip those constant bytes (usually 2 passes instead of 8).
- Resulting order: by layer; within a layer, shapes (the white texture's slot) and each sprite texture form groups ordered by texture slot; within a group, submission order. Cross-texture overlap order within one layer is not submission order.
- Shapes use a built-in 1x1 white texture, so shapes and sprites share one pipeline and one bind set layout (b0 uniforms, t0 texture, s0 sampler); a run of shapes is one draw.
- One flush = one `bmf_gpu_buffer_write` of all its instances, sorted and contiguous, appended in the ring after the frame's earlier flushes, plus one 16-byte uniform block (target size and its reciprocal) at `flush index * 256`. Draws: one per run of equal (pipeline, texture) in sorted order; layer changes alone do not split a run. Every draw is a 4-vertex triangle strip with `first_instance` = the run start and the ring offset as the vertex buffer offset.
- Bind sets are cached per (texture slot, flush index) with the texture handle they were made for. When another handle takes the slot, the old ones are retired and destroyed at the next `begin_frame` (bind sets cannot be destroyed inside a GPU frame).
- Pipelines are cached per color target format (made on first flush to that format).
- Past `max_instances` per frame, submits are dropped and counted (`stats.dropped`); nothing panics.
- Antialiasing uses no derivatives (`fwidth`): every distance is a Euclidean distance in target pixels, so its gradient length is exactly 1 and the coverage ramp is exactly 1 pixel wide. Results depend only on float arithmetic, not on the rasterizer's derivative precision; a CPU evaluation of the same formulas matches WARP exactly and the Intel UHD 770 within 1 level. Pixel-aligned edges of axis-aligned boxes stay crisp (coverage exactly 0 or 1 at pixel centers).

## Data layout
- `draw2d_state` (one static struct): GPU handles (ring, uniform buffer, white texture, sampler), pipeline cache `[BMF_GPU_FORMAT_COUNT]`, bind set cache `[256 slots][4 flushes]` with the texture id per slot, retired list (256), per-slot submitted texture ids, the view, per-layer current transforms (256 x 32 B) and camera stacks (256 x 8 x 20 B), frame pointers and counters, stats. About 56 KiB. `font_stroke` (static): the parsed segment table (853 segments x 4 B in a 1024-entry array) and per-glyph first/count; the source table (96 x {advance, polyline text}) is const.
- Frame arena per frame: `instances[max_instances]` (48 B each) and `keys[max_instances]` (8 B), both 64-byte aligned; per flush, popped again: sort temporaries (keys 8 B, order 2 x 4 B) and the sorted copy (48 B) for n instances. Default 65 536 instances = 3.5 MiB at begin_frame, up to 4.0 MiB more during a full flush.
- GPU: instance ring `max_instances * 48` bytes (dynamic VERTEX, 3 MiB by default), uniform buffer 1 KiB (dynamic UNIFORM).

## Hot paths
- Submit: one bounds check, one key, a 48-byte store. Flush: radix sort (constant key bytes skipped), a gather, one buffer write, one draw per run.
- Measured, 10 000 sprites submit + sort + gather + upload + batch, null backend, best of 200 (win64 -O2 LTO, 2026-11-21, with the camera transform at submit): 8 layers x 4 textures (32 draws) 87-94 µs (submit 34 µs; 74 µs before cameras); one layer, one texture 57-60 µs; 10 000 circles on 8 layers 72-77 µs. Target (SPEC §12.3): < 500 µs. Debug -O0: about 1.7 ms. A real backend adds the ring copy (480 KB). The benchmark scene `tests/bench/sprites10k` (1A-42: 10 000 sprites, 8 layers x 4 textures, 32 draws, positions computed per sprite in the draw callback; release `BMF_AGENT=1`, null backend, 600 frames) measures `draw` (compute + submit) p50 67 µs / p99 78..81 µs and `draw2d_flush` (sort, gather, batching) p50 57 µs / p99 66..81 µs; its perf.budget holds 250 + 250 µs (the SPEC target), checked by `build test`. On WARP the flush takes about 2.5 ms (the rasterizer runs inside the buffer map), and windowed on the Intel UHD 770 (occluded window, noisy) p50 145 µs: the ring copy and D3D11 calls cost about 90 µs.
- Text: per segment the same push as a shape plus two point mappings (no per-glyph parsing). 1000 characters centered on 10 lines (9 050 instances) submit + flush 55-57 µs, submit 22-23 µs (same harness). Debug -O0: about 1.2 ms.

## Limits
- Text: ASCII only (other code points draw a box), no kerning, no word wrap, no vertical alignment (position is the top of the box), no rotation parameter (it turns with the camera). Strokes below about 1 target pixel get faint (point-sampled coverage); size 12 at the default stroke is the smallest comfortable size. MSDF/TTF text comes in Phase 2.
- Submits are placed for `begin_frame`'s view; a flush to a target of another size draws them at the same pixel positions (no re-projection). A camera stack is per layer, not per flush.
- No non-uniform camera scale or skew (lengths need one scale).
- Coverage is point-sampled at the pixel center: shapes thinner than 1 px are drawn fainter than their true area (a 0.5 px line peaks at 75 % instead of about 50 %), and sub-pixel detail can shimmer under motion. Softness widens the ramp but is not exposed in the API yet.
- One blend mode (premultiplied); the key's pipeline field is reserved for more. No depth/order field in the API yet.
- Sprites take a raw `bmf_gpu_texture` (the asset tasks 1B-32/1B-33 decide the public texture handle). The sampler is linear/clamp for every texture (no pixel-art nearest option yet).
- At most 4 flushes per frame; bind sets used = textures x flushes and share the GPU pool of 256 (a full pool panics).
- No WGSL shader yet (1B-42); `BMF_SHADER_DRAW2D` comes from the D3D11 generated header, so draw2d builds only on Windows until then.

## Tests

The 1A-20a/b tests push the identity screen camera on every layer (target-pixel coordinates). `tests/test_draw2d_text.c` (1A-21): glyph data (every printable glyph has ink, points inside the cell margins, tabular digits, no two glyphs identical), measure values (lines, `\r`, UTF-8, invalid bytes, NUL, exact scaling), submitted instances (end points, default and explicit stroke, alignment per line, line advance, dots, replacement, world camera equal to screen camera in pixels, rotated camera, budget drops), a 672x272 WARP character sheet (all glyphs at sizes 12/20/32 plus the three alignments) compared per pixel with a CPU reference that rounds the source and result to 8 bits per blend like WARP (tolerance 1), no ink outside the measured boxes, ink within 3 px of both edges of aligned lines; the image is compared with the golden `draw2d.font`; and a 1000-character timing note.
