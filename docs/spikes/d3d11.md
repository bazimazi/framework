# Spike P0-08: D3D11 at build time and in headless mode

Date: 2026-11-18. Toolchain: llvm 23.1.6. Windows 11 26100, `d3dcompiler_47.dll` and WARP from System32. Spike code: `spikes/d3d11/` (throwaway).

## Result: works, CRT-free, no `d3d11.h`

One CRT-free exe (`d3d.c`, own entry, `kernel32.lib` only):
1. `LoadLibraryA("d3dcompiler_47.dll")` + `GetProcAddress("D3DCompile")`, compiles a VS (`vs_5_0`) and PS (`ps_5_0`) from an HLSL string with `D3DCOMPILE_OPTIMIZATION_LEVEL3` (`0x8000`), and writes both bytecode blobs as C arrays to `out/shaders_gen.h` (the shape of the future `out/gen/shaders_d3d11.h`).
2. `LoadLibraryA("d3d11.dll")` + `D3D11CreateDevice` with `D3D_DRIVER_TYPE_WARP` (5), feature level 11_0 granted.
3. Renders a clear plus one triangle (vertex positions from `SV_VertexID`, no vertex buffer or input layout) into a 64×64 `R8G8B8A8_UNORM` render target, copies it to a staging texture, maps it and writes a raw RGBA dump.

Linking needs no `d3d11.lib`/`d3dcompiler.lib`: both DLLs are loaded at runtime. (Linking `d3d11.lib`/`dxgi.lib` import libraries is also fine; runtime loading lets a headless `--no-gpu` run start on machines where D3D11 is missing.)

## Readback correctness

- Corner pixel `(0,0,255,255)` (clear), center `(255,128,0,255)` (triangle; 0.5 → 128 with UNORM round-to-nearest), 1 352 covered pixels.
- `RowPitch` was 256 for a 64-pixel row; the copy loop honors `RowPitch` (must not assume `W*4`).
- Three runs produced byte-identical dumps (md5 `a1ed8aba5a9c...`): WARP is deterministic run to run on this machine, as golden images need.

## Required vtable slots (verified against SDK `d3d11.h`)

A host-only check (`vtcheck.c`, includes the SDK headers, uses the CRT; covered by amendment A-01) prints `offsetof(<I>Vtbl, Method) / 8`. All hand-declared slots match:

| Interface | Method: slot |
|---|---|
| `ID3DBlob` (`ID3D10Blob`) | GetBufferPointer 3, GetBufferSize 4 |
| `ID3D11Device` | Release 2, CreateTexture2D 5, CreateRenderTargetView 9, CreateVertexShader 12, CreatePixelShader 15 |
| `ID3D11DeviceContext` | Release 2, PSSetShader 9, VSSetShader 11, Draw 13, Map 14, Unmap 15, IASetPrimitiveTopology 24, OMSetRenderTargets 33, RSSetViewports 44, CopyResource 47, ClearRenderTargetView 50 |

Struct sizes also match: `D3D11_TEXTURE2D_DESC` 44, `D3D11_VIEWPORT` 24, `D3D11_MAPPED_SUBRESOURCE` 16. Constants used: WARP 5, BIND_RENDER_TARGET 0x20, CPU_ACCESS_READ 0x20000, USAGE_STAGING 3, MAP_READ 1, TRIANGLELIST 4, R8G8B8A8_UNORM 28, FEATURE_LEVEL_11_0 0xb000, SDK_VERSION 7, CREATE_DEVICE_BGRA_SUPPORT 0x20.

Declaration style that worked: one vtable struct per interface, typed function pointers for used slots, `void* _<slot>_<Name>` placeholders for unused slots, so the slot number is visible in the name. Recommendation for 1A-10/1A-14: keep this style, and make the `vtcheck` program the 1A-14 test (`tests/test_vtable_slots.c`), generated over **every** declared method, not a hand-picked list.

## Timings

| Step | Time |
|---|---|
| `LoadLibrary(d3dcompiler_47)` + two `D3DCompile` calls (tiny shaders) | 8.1 ms |
| `D3D11CreateDevice` (WARP) | 4.5–6.0 ms |
| Bytecode size | VS 688 bytes, PS 452 bytes |
| Exe size | 10 752 bytes (includes the embedded HLSL and JSON output code) |

WARP device creation is cheap enough for every headless test run and well within the 100 ms startup target.
